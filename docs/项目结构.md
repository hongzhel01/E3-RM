# E3-RM 项目结构

本文介绍当前可运行框架的组织方式。E3 专属数据变体、附加损失和渐进调度仍在设计阶段，尚无独立实现目录。

## 目录总览

```text
E3-RM/
├── README.md                         # 安装、数据、训练、评分与恢复说明
├── pyproject.toml                    # 版本、依赖、命令、打包和检查配置
├── .gitignore                        # 排除环境、缓存、数据和训练输出
├── e3_rm/                            # 唯一 Python 源码包
│   ├── __init__.py                   # 公开 API 与延迟导入
│   ├── _lazy_module.py              # 按需加载模块
│   ├── _compat.py                   # 依赖兼容处理
│   ├── import_utils.py              # 可选依赖检测
│   ├── data_utils.py                # 数据格式、消息和分词工具
│   ├── chat_template_utils.py       # 模板识别、修补与响应解析
│   ├── distributed.py               # 分布式后端封装
│   ├── trainer/                     # 七种训练器、配置和共享工具
│   ├── cli/                         # 命令注册、解析和 Accelerate 启动
│   ├── scripts/                     # 包内训练脚本与参数/数据加载工具
│   ├── models/                      # 参考模型、激活卸载和检查点工具
│   ├── generation/                  # vLLM 通信及生成后端
│   ├── rewards/                     # 策略训练使用的奖励函数
│   ├── kernels/                     # 分块概率、熵和散度计算
│   ├── extras/                      # 被训练/生成使用的性能计时工具
│   ├── chat_templates/              # 75 个被直接引用的 Jinja 模板
│   ├── templates/                   # 模型卡、奖励模型卡与数据卡模板
│   ├── accelerate_configs/          # 9 个单卡/分布式配置
│   ├── licenses/                    # 继承源码的许可证正文
│   └── py.typed                     # 类型信息标记
├── tests/                           # 方法、共享功能与本地集成测试
└── docs/
    ├── 项目结构.md                   # 本文
    ├── 设计与实验.md                 # E3 方法目标、数据与实验定义
    ├── 开发与迁移.md                 # 开发约定、兼容边界与检查方法
    └── 整理记录.md                   # 精简结论与验证记录
```

`.git/` 是版本库元数据，不属于运行代码，也不纳入精简删除。安装、测试或训练时产生的 `.venv/`、缓存、`data/`、`configs/` 和 `outputs/` 不一定预先存在；需要时再创建，不放空占位目录。

## 三种名称

| 用途 | 名称 | 示例 |
| --- | --- | --- |
| 项目展示 | E3-RM | README 标题 |
| Python 分发与命令 | `e3-rm` | `e3-rm reward --help` |
| Python 导入 | `e3_rm` | `from e3_rm import RewardTrainer` |

版本统一声明在 pyproject。公开 API 使用标准算法类名，便于识别方法；根包通过延迟导入，避免未使用的可选功能提前加载。

## 训练器与配置

| 方法 | `e3_rm/trainer/` 中的主要文件 | 输入与职责 |
| --- | --- | --- |
| Reward | `reward_trainer.py`、`reward_config.py` | 成对偏好数据，学习标量奖励 |
| SFT | `sft_trainer.py`、`sft_config.py` | 指令、文本或对话，监督生成训练 |
| DPO | `dpo_trainer.py`、`dpo_config.py` | 结合策略与参考概率进行偏好优化 |
| KTO | `kto_trainer.py`、`kto_config.py` | 可取/不可取二元反馈 |
| GRPO | `grpo_trainer.py`、`grpo_config.py` | 同问题候选组、奖励与组内优势 |
| RLOO | `rloo_trainer.py`、`rloo_config.py` | 用同组其他候选构造留一基线 |
| Distillation | `distillation_trainer.py`、`distillation_config.py` | 教师分布指导学生训练 |

`base_config.py` 继承通用训练参数，`base_trainer.py` 提供少量公共训练支持与模型卡保存。`model_config.py` 定义模型、LoRA 和量化参数；`utils.py`、`callbacks.py` 服务多个方法。

这些训练器相对独立，存在有意复制的生成和记录流程。修改同义代码时应检查所有副本，避免仅修一个训练器。

## 命令如何进入训练

```text
e3-rm reward --config configs/reward.yaml
  → pyproject 中的 e3_rm.cli:main
  → cli/main.py 与 commands/ 注册、选择子命令
  → commands/training.py 分离训练参数和启动参数
  → cli/accelerate_launcher.py 定位包内脚本并启动
  → scripts/reward.py 加载配置、数据、模型并创建训练器
  → trainer/reward_trainer.py 执行训练、评估和保存
```

`e3_rm/scripts/` 是安装包的运行入口，不能与已移除的根目录开发脚本混淆。参数解析器是 `E3RMParser`；内置 Accelerate YAML 通过包资源定位，不依赖在源码目录执行。

## 奖励模型的数据流

原始偏好对经过分词、聊天模板、长度过滤和 padding 后，collator 将 chosen 放在批次前半、同顺序 rejected 放在后半。模型为每个序列输出一个奖励，训练器按配对计算损失并记录排序准确率等指标。

数据字段、样本顺序、有效 token、评分头和保存方式均影响结果。未来加入 E3 变体时，需要扩展列保留、分词和批次索引，不能只增加损失后继续均分所有输出。

## 为什么这些目录继续保留

- `chat_templates/`：75 个文件均被 `chat_template_utils.py` 直接加载，包含格式识别和训练修补用途。删除任意引用目标可能导致导入失败。
- `generation/`、`rewards/`：GRPO/RLOO 等方法需要生成和奖励信号，不能因当前研究聚焦奖励模型而删除。
- `kernels/`、`extras/`、`distributed.py`：被蒸馏、生成和公共工具实际使用。
- `models/`：提供冻结参考模型、卸载和分布式生成支持，不只是模型骨干定义。
- `templates/`：训练输出会读取这些卡片模板，属于打包资源。
- `licenses/`：保存继承源码的授权正文；原始版权头也继续保留。

目前没有闲置聊天模板、旧本地包或上游实验算法目录。外部模型/数据集 ID 和有效源码参考链接保留真实名称，不将它们改成不存在的项目资源。

## 按任务寻找代码

| 任务 | 建议入口 |
| --- | --- |
| 修改奖励损失 | `trainer/reward_trainer.py`，E3 方法应使用独立子类 |
| 修改训练参数 | 对应的 `*_config.py`；通用模型参数见 `model_config.py` |
| 修改数据格式 | `data_utils.py` 与对应训练器的数据预处理/collator |
| 修改 CLI 参数或数据来源 | `scripts/utils.py` 与对应 `scripts/<method>.py` |
| 调查保存/重载 | 对应训练器、`base_trainer.py`、`templates/` |
| 修改生成或多卡同步 | 对应训练器、`generation/`、`distributed.py`、`models/utils.py` |
| 验证本地最小闭环 | `tests/test_local_training.py` |
| 实现 E3 方法 | 先阅读[设计与实验](设计与实验.md)，再增加实际需要的模块 |

## 测试组织

`test_local_training.py` 使用本地随机 tiny 模型，覆盖七种训练方法、权重保存/重载、LoRA 评分头和冻结参考模型。其他 `test_*` 文件验证各训练器及工具；`tests/data/` 是测试资源，`tests/distributed/` 需要相应硬件，`tests/invariant/` 保存 SFT/DPO 的训练不变量检查。

默认只收集主项目 `tests/`，不自动运行训练不变量目录。完整测试可能需要联网、额外依赖或 GPU；本地闭环成功不代表正式任务效果或 E3 方法已经验证。
