# README 与实现核查

本次按 README 的训练目标、数据约束、CLI、评估及恢复流程逐项核对。核心四项机制均已落地；进一步检查发现了正常冒烟测试未覆盖的训练与统计问题，已添加真实 tiny 模型回归测试并修复。

## 已复现并修复的问题

| 优先级 | 问题与影响 | 修复与对应验证 |
| --- | --- | --- |
| 高 | 微批次关系密度不一致时，原实现平均每个微批次的损失均值，导致梯度累积不等价于同一有效大批次；不完整尾批也会改变基础偏好权重。 | `E3RewardTrainer.get_batch_samples` 统计整个优化器更新窗口的各项有效分母；各进程对分母求和，避免再次除以微批次数。使用 SGD 比较一次大批更新与含尾批的梯度累积，逐参数验证一致。 |
| 高 | `eval_loss` 按原始样本数平均批次损失，混淆不同附加关系的分母。复现中仅将评估批大小从 2 改为 1，损失从约 1.498 变成 1.098。 | 在评估循环返回前，根据各项关系损失的全数据集和与计数重建联合目标，包含奖励中心化；`evaluate`、`predict`、日志与最佳模型选择使用相同结果。 |
| 高 | 已有四个 token 列便直接返回，预分词数据可以绕过长度过滤、来源 ID、验证标记和语义方向校验。 | 原始与预分词路径统一验证、过滤；预处理结果保留 `verified`，缺少验证标记的旧关系须重新生成。测试覆盖超长原始对、超长变体、错误 sign、缺失验证标记与空来源。 |
| 高 | 隐式对话的原始回答包含用户问题，回答形式的变体却没有补回共享 Prompt，导致在不同上下文下施加一致性约束。 | 提取原始对话共享消息前缀，统一拼接到变体及语义变化回答；测试直接核对最终 token 序列。 |
| 中 | 启用 E3 但数据缺少有效关系时，各附加项始终为零，用户可能将普通偏好训练误认作完整 E3。 | 非流式预处理检查各项有效覆盖量，对正系数但无有效关系的目标发出提示。流式数据不被强行耗尽，整体覆盖仍须上游检查。 |
| 中 | 自定义评估前缀或多验证集时，权重和 token 日志仍写成 `eval_*`，污染不同数据集的指标命名。 | 评估循环按调用者的 `metric_key_prefix` 聚合全部 E3 指标，测试 `test_*` 及命名验证集。 |
| 中 | 训练前单独评估时是否设置 `max_steps` 会改变附加项系数：同样的未训练模型可能被当成阶段一，也可能使用最终权重。 | 以已建立的 `TrainerState` 训练进度判断课程是否启动；训练前评估统一使用最终系数，训练过程中使用当前权重。 |

这些回归用例位于 [`tests/test_e3_reward.py`](../tests/test_e3_reward.py)。两进程检查位于 [`tests/distributed/test_e3_cpu.py`](../tests/distributed/test_e3_cpu.py)，用于比较分布式梯度与单进程梯度，以及样本补齐后的指标分母。

## 四项创新点及调用链

- 奖励不变性：`e3_loss_terms` 计算原始回答与已验证等价变体的平方奖励误差。
- 差值一致性：同一条变换关系两侧齐备时建立四元组，比较原始与扰动后的偏好分差。
- 语义敏感性：独立 sign 标签控制带正 Margin 的 hinge 排序方向，事实错误不会自动进入等价关系。
- 渐进课程：`get_e3_weights` 按优化器更新次数计算线性权重，`compute_loss` 选择当前启用关系并构造联合目标；`TrainerState.global_step` 随检查点恢复。

CLI 的 `e3-rm reward --e3 true` 选择 `E3RewardTrainer`；Python API 直接使用 `E3RewardConfig` 和 `E3RewardTrainer`。原始 `RewardTrainer` 的目标保持为基线。

## 尚未完成或不能由当前测试证明的部分

- **实验范围**：已完成 7 万参数随机 GPT-2 的三种子受控消融实验及近似等 token 基线，共 21 次对照训练，结果见[设计与实验](设计与实验.md)。7B/14B、真实偏好数据和下游 Reward Hacking 改善仍未验证，不能将合成任务结果外推为真实任务结论。
- **变体生成与语义验证**：训练器消费已验证关系；新增实验运行器能生成并核验有限模板中的值/单位关系，不提供自然语言通用改写、硬负样本生成或语义等价证明器。
- **硬件验证**：本地 tiny 模型覆盖 CPU 训练、LoRA、流式数据、对话与恢复路径；QLoRA、DeepSpeed、FSDP 和多 GPU 仍需相应硬件上的单独验证，不能从 CPU 测试推断全部组合已验证。
- **来源隔离**：来源检查依赖调用者正确维护 `source_id`，不会证明不同 ID 的语义独立性；流式集合不被遍历以检查跨集合重复。
- **课程恢复**：相同总步数与调度参数下测试续训一致性。修改总步数、阶段起点或系数会改变课程含义。
- **推理长度**：README 示例改为拒绝超长候选，避免推理时静默截断关键事实，与训练的整对过滤语义冲突。

## 验证原则

测试使用真实的本地随机初始化 tiny GPT-2、Tokenizer、Dataset、优化器及 Trainer，不下载模型权重，不用伪造训练器替代真实调用。单元测试证明数学与工程行为；方法效果须由正式实验评估。

最新定向回归 **86 项通过**，包含 E3、实验数据与统计校验、两进程 CPU/Gloo、原有七类训练器及 Reward LoRA 的本地集成测试、CLI 帮助和恢复参数、原始奖励 collator。另通过 `ruff check e3_rm tests`、差异空白检查、依赖检查和 Wheel 构建。验证环境为 Python 3.11、PyTorch 2.15、Transformers 5.21；未将此结果外推为所有最低依赖版本和 GPU 后端的兼容性证明。
