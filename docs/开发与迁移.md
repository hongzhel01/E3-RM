# E3-RM 开发说明

## 配置与依赖

项目使用 `e3-rm` 分发名、`e3_rm` 导入包及 `e3-rm` 命令。版本、依赖、extras、打包、pytest 与 Ruff 配置集中在 `pyproject.toml`。安装与使用步骤见 [README](../README.md)。

默认安装只包含基础依赖；LoRA、量化、vLLM、DeepSpeed 等按需安装。当前最低版本声明不是所有硬件组合均已验证的承诺。GPU 训练需匹配 PyTorch、驱动、精度和相应后端。

## 模型与数据

`RewardTrainer` 加载单标签序列分类模型，对每个回答输出标量奖励。普通文本偏好对将问题和回答拼接后处理；对话数据使用匹配的聊天模板。`max_length` 会过滤超长偏好对，应检查剩余有效样本数。

正式实验先固定数据划分，避免同源样本及其变体跨集合。CLI README 示例仅进行训练；独立验证集使用 Python API 显式传入。

## LoRA 与 QLoRA

奖励模型的 LoRA 配置应明确序列分类任务，并保存评分头：

```python
from peft import LoraConfig, TaskType

peft_config = LoraConfig(
    task_type=TaskType.SEQ_CLS,
    r=8,
    lora_alpha=16,
    target_modules="all-linear",
    modules_to_save=["score"],
)
```

通过 `RewardTrainer(peft_config=...)` 传入。QLoRA 另外配置 `BitsAndBytesConfig` 并使用训练器的 `quantization_config` 参数；量化不代表新评分头会自动训练。完整模型与 adapter 的保存、重载路径应分别检查。

适配器可使用 `peft.AutoPeftModelForSequenceClassification.from_pretrained(adapter_dir)` 加载，基座目录或模型 ID 必须仍可访问。继续训练适配器时按 PEFT API 开启训练状态，不将最终 adapter 导出目录当作完整优化器 checkpoint。

## 分布式与资源

Accelerate YAML 统一位于 `e3_rm/accelerate_configs/`。CLI 可接收内置名或用户路径。单卡配置为 1 个进程；多卡、ZeRO、FSDP、context parallel 和 ALST 配置需要按设备覆盖进程数、精度与机器数量。

聊天模板、模型卡及 YAML 是实际运行资源。当前 75 个聊天模板被模块直接引用；仅删除文件而不调整调用与测试会破坏功能。包资源应使用包路径加载，不依赖用户工作目录。

## 代码与注释规范

保留现有 API 和变量名，以中文注释解释设计原因、张量形状、样本布局、mask、标签方向和有效分母。避免逐句翻译赋值语句，或把尚未实现的 E3 约束写成现有行为。

训练器相对独立，生成、同步和记录逻辑可能有意复制。修改同义模式时检查每个副本和调用方，保持同义代码与注释一致；方法差异须有明确语义依据，不在单个副本暗改数值逻辑。

优先采用简单实现，不为精简文件而制造巨型工具文件，也不增加不必要的注册器或兼容层。测试使用真实 tiny 模型、tokenizer 和 Dataset；仅在远程服务边界使用必要模拟。

许可证与原始源码版权头保留。论文方法的来源、对应代码和验证结果记录在[设计与实验](设计与实验.md)。具体目录分工见[项目结构](项目结构.md)。

## 兼容与验证

旧脚本应使用当前包名和命令，当前项目不提供旧命名的转发包。外部 Hugging Face 模型/数据集 ID、官方 API 和来源链接保留真实名称，不能替换为不存在的 E3-RM 资源。

常规模型权重、adapter、tokenizer、序列化参数与完整训练状态需要分开验证。旧 checkpoint 可能记录旧模块路径，不能保证直接恢复；可在原环境导出标准权重，在当前环境显式重建配置。不要对二进制权重进行字符串替换。

默认测试只收集 `tests/`，训练不变量目录需显式运行：

```bash
python -m pytest tests/test_local_training.py -q
python -m pytest tests/test_reward_trainer.py -q
python -m pytest tests/test_cli.py tests/test_cli_utils.py -q
python -m pytest tests/distributed -q
python -m pytest tests/invariant -m invariant -q
ruff check e3_rm tests
python -m build
```

模型下载、量化、服务和多卡检查需要相应网络、依赖及硬件。跳过、未运行、失败和通过应分别记录。历史训练验证与本轮整理检查见[整理记录](整理记录.md)。

分发包应包含所需模板、配置与许可证正文。构建后检查 wheel/sdist 中的资源和许可证，安装验证应在源码目录外进行，避免依赖未声明的源码路径。
